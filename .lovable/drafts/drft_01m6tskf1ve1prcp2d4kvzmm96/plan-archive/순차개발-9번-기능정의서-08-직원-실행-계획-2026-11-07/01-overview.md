# 순차개발 9번(기능정의서 08) 직원 실행 계획

개발 공간 격리 점검은 지금 실행 환경에서 다시 통과했습니다(차단 적용 후 검사 21개 모두 통과).

## 만드는 것
- 직원은 **본인이 대상자로 참석 처리된** 교육·필드 코칭·매니저 코칭 한 건마다 실행 계획 하나를 쓰고 고칠 수 있습니다.
- 「실행 계획·후속 확인」 화면(현재 예시 화면)을 실제 화면으로 바꿉니다.
  - 내 계획: 작성 가능한 교육·코칭 목록 → 계획 작성·저장 → 상세 다시 보기
  - 담당자 보기: 기존 담당 범위에 맞는 직원 계획만 읽기 전용으로 표시
- 불러오는 중, 오류, 아직 없음 상태를 모두 보여줍니다.

## 지키는 기준
- 검수 계정이 아니면 서버에서 거부합니다.
- 다른 직원 계획, 담당 지점 밖, 다른 종류 코칭의 담당자는 읽기·수정 모두 차단합니다. 트레이너는 매니저 코칭 계획을, 스토어매니저는 다른 매니저의 코칭 계획을 볼 수 없습니다.
- 담당자는 계획을 고칠 수 없습니다. 학습 시간·진도·수료·참석은 바꾸지 않습니다.
- 정하지 않은 기준(글자 수 외 수정 기간, 버전 보존, 판정)은 만들지 않습니다. 글자 수는 기존 코칭과 같이 5,000자로 둡니다. 후속 확인(다음 기능)은 만들지 않습니다.

## 검수
- 시험 직원 계정으로 실제 로그인 → 작성 → 저장 → 새로고침 → 내용 유지 확인
- 다른 직원·미지정 관리자·범위 밖 사용자·다른 종류 담당자로 화면 주소와 직접 요청 모두 차단 확인
- 서버 규칙 검사 파일을 프로젝트에 추가하고 기존 검사와 함께 실행, 기존 학습 화면·메뉴 회귀 확인

## 기술 메모
- 새 표 `mygrowth_action_plans`(training_id, user_id 고유, body, original_language, 작성·수정 시각). 화면에서 직접 읽기·쓰기 권한 없음, 서비스 역할만 전체 권한.
- 저장 함수 `mygrowth_save_action_plan`: 검수 계정 + 본인 + 참석 대상 확인 후 저장.
- 조회 함수 `mygrowth_my_action_plans`, `mygrowth_scoped_action_plans`: 담당자 조회는 기존 `mygrowth_session_scope`를 그대로 사용해 종류별 범위를 유지합니다.
- 초안은 수락·게시하지 않습니다.
